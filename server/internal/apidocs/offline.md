# 离线与故障

## 1. 先按错误分类

| 情况 | 有合法签名缓存 | 无合法缓存 | 缓存处理 |
| --- | --- | --- | --- |
| 断网、超时、TLS 失败、非 200、HTML、解密/签名/请求绑定失败 | 仅在原签名宽限内运行，不能返回 online | 返回原错误 | 不清缓存，不写 Refused |
| 已认证临时错误 | 同上 | 返回原错误 | 不清缓存，不写 Refused |
| 已认证明确拒绝 | 立即失败，不宽限 | 同样失败 | 清 proof，写 Refused |
| INSTANCE_REPLACED | 旧进程立即停止，不宽限 | 同样失败 | 不破坏共享的普通授权缓存，不写 Refused；清载荷密钥缓存及启动桩证据 |
| 授权到期、宽限耗尽 | 停止业务 | 停止业务 | 不能延长原窗口 |
| 试用、首次激活、空卷 | 必须联网 | 必须联网 | 不提供首次离线激活 |

临时错误仅包括 `INTERNAL_ERROR`、`RATE_LIMITED`、`LOG_UNAVAILABLE`、`REPLAY_DETECTED`、`TIMESTAMP_INVALID`、`SIGNATURE_INVALID`、`INVALID_REQUEST`、`PAYLOAD_INVALID`。所有未知的已认证非 OK 错误默认拒绝；未完成认证的错误码不可相信。[完整规则](?tab=protocol#7-错误码与故障状态机)。

## 2. 再检查缓存、时间和席位

1. 保留每实例独立缓存卷；共用卷可能使常驻进程互相接管，删除卷会失去身份和签名证据。
2. 检查缓存目录权限。新实例无法建立目录可仅在内存运行；已有缓存目录变只读时，故障回退仍须保存时间水位，失败返回 `SDK_CACHE_UNAVAILABLE`。
3. 校准系统时间。本机比缓存最晚时间早超过 300 秒时返回 `SDK_CLOCK_ROLLBACK`；在线验证成功才能重建可信水位。
4. 浮动租约已过期时，正式授权仍可在原 `grace_until` 内进入宽限；服务恢复后重新竞争席位，满额立即拒绝。
5. 宽限窗口由软件设置决定，到期优先。`SDK_GRACE_EXPIRED` 保留触发故障的原始原因。

## 3. 处理业务状态

- 宽限不是最终失败；常驻程序最终失败应退出 77，PHP 请求式返回 HTTP 503，不结束服务进程。
- 正常停止常驻程序释放席位；崩溃或 PHP 请求式依赖租约回收。
- 更新检查的所有结果均不修改授权缓存；SDK 公告读取不要求激活，也不改变授权状态。
- 代码加密程序必须先有合法授权证据，再解锁代码；空卷、试用或零宽限不能借旧密钥断网启动。`PAYLOAD_INVALID` 不代表吊销，不清授权缓存。

## 4. 收集排查信息

先检查服务地址、网络、HTTPS 证书和代理，再查授权状态。记录错误码、HTTP 状态、版本、时间、缓存是否可写，不记录授权码、配置、令牌或内容密钥。不要放宽签名或 TLS 检查。
