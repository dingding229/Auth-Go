# 给客户的运行说明

## 1. 启动程序

取得软件提供方的 Compose 文件，填写授权码后启动：

```sh
docker compose up -d
docker compose logs --tail=50
```

只填写 `AUTHGO_LICENSE`；不要修改程序内的接入配置。启用免授权码试用的软件可留空授权码，试用必须联网。

## 2. 缓存卷、扩容与席位

- 每个实例使用独立缓存卷。保留卷重建仍是原实例；删卷后必须重新联网激活。
- 缓存不可写时可能仅在内存运行，重启后没有断网宽限，应修正卷权限。
- 常驻程序正常停止会释放席位；崩溃且不重启时，两个心跳间隔后回收。滚动更新新旧实例重叠需要额外席位。
- 多个常驻副本共用一个卷会互相替换；PHP 请求式无法可靠区分共用卷的副本，严格实例限制应选常驻模式。
- PHP 请求式停止容器不会立即释放席位，空闲时靠租约回收，下次请求重新竞争。
- 后台“释放席位”删除实例记录，但仍在运行的程序可能重新占位；要阻止运行，应暂停或吊销授权。

## 3. 断网与授权失败

| 情况 | 处理 |
| --- | --- |
| 首次激活、空卷、试用 | 必须联网 |
| 已有合法缓存且连接故障 | 正式授权仅在软件允许的原签名宽限内运行 |
| 到期、席位满、吊销、版本禁用等明确拒绝 | 停止业务，联系软件提供方 |
| 常驻程序最终失败 | 退出 77，查看容器日志 |
| PHP 请求式最终失败 | 返回 HTTP 503 和错误码，容器不退出 |

不要通过删卷、改时间或禁用证书检查恢复授权。更新提示只提供镜像信息，不自动替换程序。详细分类见[离线与故障](?tab=offline)。

## 4. 反向代理与真实 IP

业务端口按软件提供方说明映射；如仅供本机代理访问，将端口绑定 `127.0.0.1`，对外使用 HTTPS。

运维 Auth Go 授权服务器时，在“系统设置”填写 HTTPS 对外服务地址。受信代理为空时，默认信任环回、RFC1918 私网、链路本地和 IPv6 ULA 的直接对端；从 `X-Forwarded-For` 自右向左取首个非受信地址，无此头才用 `X-Real-IP`。公网直接对端的转发头一律忽略。

填写受信代理后仅信任配置的 IP/CIDR，不再附加私网。代理须覆盖并传递 `X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`；仍标记“内网”时检查这些头，不要信任全网或不可信容器。

Auth Go 官方 Compose 发布 `8080:8080`。数据库与 `master.key` 一起备份；不要用 `docker compose down -v` 删除数据。安装及备份见 [README](https://github.com/dingding229/Auth-Go#日常运维)。

## 5. 联系软件提供方

提供错误码、版本、发生时间和缓存卷是否保留，不公开授权码、配置、令牌或缓存文件。IP 库和疑似共享仅辅助排查，不能仅凭 IP 判定共享。

授权服务器管理员可在“系统设置 → IP 库”启用 UTC cron 定时同步，默认 `0 3 1 * *`，间隔至少 1 小时。来源固定为 DB-IP 免费库；开启后下次同步会替换上传库，失败保留原库并退避重试。
